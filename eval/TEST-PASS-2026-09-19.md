## Task 6: judge read (Path One criteria, 1 to 5)

1. **Meaningful use of Sanity Context and structured content: 4.** Observed: all 18 answered questions began with `groq_query` over the rules dataset through the Context GROQ endpoint, and the structured fields did the work: `effectiveTo` drove q08 ("effective 2022-05-23 to 2025-09-11, now superseded"), `contradictionId` and `resolution` drove q06 (C4, "unresolved") and q09 (C5, authority 80 over 60), `appliesWhen` drove q13 ("no threshold in appliesWhen"). The Rules on file panel and the /contradictions ledger render the same documents without the model. Not a 5 because the time travel feature, the strongest structured content demo, could not be observed today, and because 3 of 18 queries still used ad hoc title filters.
2. **Technical implementation and code quality: 3.** Observed: clean separation (context.ts, prompt.ts, counsel.ts, ratelimit.ts, insights.ts), ed25519 verification and deferred response on the Discord route, dynamic tool parts handled. Against: one unfunded test key with no fallback took the whole demo down; the error surfaced to visitors is the generic "An error occurred."; two MCP clients are opened per request with no reuse; the rate limiter is per instance; the eval runner has no back off and 429'd itself 15 times; three unused privileged intents are toggled on in the portal.
3. **Use of Knowledge Bases: 3.** Observed: the KB endpoint's initial context is inlined into the system prompt on every request, and `knowledge_base_read` was called in 2 of 18 answers (q04 read `gateway_api` and `privileged_intents/thresholds_and_policy`, q15 read `developer_policy/developer_policy_editions`). The KB build resolved one real conflict (Monetization Terms dates) and carries two instructions. But the KB is second fiddle by design ("SECOND step only") and most answers never touch it; a judge looking for the KB doing the reasoning will see the GROQ dataset doing it instead.
4. **Usability: 3.** Observed: the Discord DM skin is legible at 390 px, streaming works, rulings are colour coded, sources are links, the ledger is public. Against: the first example question yields no ruling, q16 also yields no ruling, median answer is around 350 words under a "one sentence ruling" promise, and right now every question fails with a generic error.

"Would a keyword search have gotten the same answer" on three answers:
- **q13 (privacy policy for one private server): yes.** Searching "privacy policy" in the Developer Terms returns the same clause; the agent adds only the `appliesWhen` observation that there is no size threshold. Keyword search wins on cost.
- **q09 (retry_after seconds or ms): no.** A search returns both the docs table ("The number of seconds to wait") and the support article ("Milliseconds to wait") and leaves the developer to pick. The ruling came from `authority` (80 vs 60), the change log date (2020-09-24) and the C5 `resolution`, none of which a search has.
- **q01 (150 servers, 4,000 users): no.** A search for "100 servers" returns the stale flags table as a live rule. The correct answer needed `effectiveTo: 2026-06-09` on the old rule and `appliesWhen.maxUsers` on the new one, plus the developer's own user count. That is the structured content earning its place.
