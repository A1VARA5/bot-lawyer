## Patterns

1. **Knowledge base summary text quoted as page wording (q21, q24, k02).** The Sanity Context knowledge base returns entries written about a page, not the page. The model puts sentences from those entries inside a blockquote with the page's URL under it. In q21 that produced a quote that is not on the page and is wrong on the rule (verification tied to 10,000 users; the dataset's C2 says the two reviews are separate). In q24 it produced a garbled title and a URL cut to `/hc/en-us/articles`. In k02 it produced an inline quote that is a paraphrase. This is the one defect in three runs that a developer could act on and be wrong. Fix, one prompt paragraph: blockquotes only from a rule's `quote` field; when a knowledge base entry is the source, write "the knowledge base summary of [page] says" and no blockquote and no URL under it.
2. **One answer was empty on the first pass because of the output token ceiling.** k01 asked for two verbatim clauses and a comparison, the longest expected answer in the set; the first run ended with finishReason length and no text at 33.8 s, because the cap was 1400 output tokens. Raised to 3000 and rerun once; the rerun took 28.6 s and passed. Nothing else about the answer was touched. Worth stating in the post because a reader who runs the same question would otherwise hit it.
3. **The draft format holds for the block, not the count.** Both drafts produced the ```md block and one Length line, and both Length numbers are wrong (393 for a 440 character block, 129 for 111). q33 also added a narration line before the fence. The model is estimating, not counting. Fix: compute the length in the app and append the Length line in code, then the model only writes the block.
4. **Title and quote match filters are back.** 6 of 22 first queries (k03, k04, q26, q30, q31, u02) filter by `title match` or `quote match` despite the prompt. u02 paid for it: the deletion of FAQ 4404772028055 is recorded in `source.what-are-privileged-intents.notes`, and no query in the run projects source notes, so the agent said the page "may be an older or unofficial page" when the dataset knew it was deleted. Fix: add `notes` to the source projection in the tool description's example query.
5. **Slower and longer, because every question now reads the knowledge base.** 20 of 22 answers made a `knowledge_base_read` as a second step (2 of 18 in run 2). Average time went from 14.7 s to 25.5 s and the median answer is 197 words. The KB read earned its keep on k01, k03, k04 and q20 (page structure and facts not in the rules dataset) and caused the q21 failure. It should stay for kb-only and "what does the page say" questions and be optional for the rest.
6. **Style leaks are down to noise, one new kind.** 2 em dashes (one in prose), 2 exclamation answers, 2 narration answers, 0 raw enum labels, 0 dates inside blockquotes. The new leak is internal ids and rule titles in prose ("rule `rule.intent-annual-reapply`", a rule title cited as a source in q31). One prompt line: never print a rule id or rule title, print the source title.
7. **u03 and q12 style fixes from run 1 held.** u03 now carries the undated-announcement caveat; q24 and q25 match their run 1 verdicts.

Ranked fixes: 1 (KB quotes) first, it is the only correctness defect; then 3 (count in code) and 4 (source notes projection) since both are mechanical; then 6.
