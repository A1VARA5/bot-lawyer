**Answer:**

No conflicts flagged on the relevant current rules. Answering from the current (2024-07-08 effective) Developer Policy and Terms plus the intent review guidance for MESSAGE_CONTENT storage.

**Ruling:** Yes, you can store user IDs and message content, but only as much as your app's stated functionality actually needs, and you must delete it once it's no longer needed.

**Why:** Current Developer Policy, effective from 2024-07-08:
> "You may not request, access, or use API Data for any purpose other than as necessary to provide your Application's stated (and approved through App Review, as applicable) functionality; provided that you may also use API Data for the purpose of improving your Application only if it has been aggregated or de-identified such that it cannot be associated with, or used to identify, any individual."
Source: [Discord Developer Policy (current, effective July 8, 2024) (developerPolicy)](https://support-dev.discord.com/hc/en-us/articles/8563934450327-Discord-Developer-Policy)

Deletion duty, same effective date:
> "you will (1) promptly update the API Data upon request from us or the applicable user, and (2) promptly delete the API Data when: (a) retaining it is no longer necessary for your Application's stated (and approved through App Review, as applicable) functionality that is permitted under the Terms; (b) you stop operating your Application... (c) we request you delete it; (d) the applicable user requests you delete it; or (e) required by applicable laws or regulations."
Source: [Discord Developer Terms of Service (current, effective July 8, 2024) (developerTerms)](https://support-dev.discord.com/hc/en-us/articles/8562894815383-Discord-Developer-Terms-of-Service)

Because you have MESSAGE_CONTENT, if that data is stored (not just processed and discarded), the intent review process, effective from 2026-06-10, requires you to disclose this:
> "If you're storing the data, explain why it's necessary and describe your retention policy and security measures. If you're processing it in memory and discarding it, say so."
Source: [Getting Started with Privileged Intent Review (developer docs)](https://docs.discord.com/developers/gateway/getting-started-with-privileged-intent-review)

**Watch out:** Three hard bans stack on top of the general rule: you must encrypt stored API data at rest (Developer Terms, effective 2024-07-08), you may not use message content to train ML/AI models without Discord's express permission (Developer Policy, same date), and you must maintain a public privacy policy describing exactly what you collect, use, share, and how users can request deletion. There is no numeric retention window in any current document, "no longer than necessary" is the only standard.

**Counsel notes:** "Necessary for stated functionality" is doing all the work here; document your reason now, not when the review form asks for it.
